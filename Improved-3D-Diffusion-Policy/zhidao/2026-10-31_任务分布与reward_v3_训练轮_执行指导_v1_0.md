## 2. 代码改动

所有改动都要满足：**默认配置下与旧实现逐位一致**；测试先行；冒烟测试用真实 E5 runtime。

### 2.1 任务库采样器

- 新增 `TaskBankMixtureSampler`，放在 `rl/dppo_uav_rebuild/environments/task_sampler.py` 中，与 `RoleBalancedTaskSampler` 并列。每个回合按下表比例选择来源：

| 来源 | 比例 |
|---|---:|
| 原采样器（原样调用 `RoleBalancedTaskSampler`，含 mid-state 初始化） | 0.15 |
| L0 | 0.10 |
| L1 | 0.15 |
| L2+L3 · 随机起点 | 0.30 |
| L2+L3 · 近障起点 | 0.20 |
| L4 | 0.10 |

- 层内抽样分三步：
  1. 先按世界类别分配：受阻层（L2–L4）密集世界 0.8、稀疏世界 0.2；L0、L1 各 0.5。
  2. 再在该类别的世界之间均匀选一个世界。
  3. 最后在该世界、该层的候选任务里均匀抽一个。
- 来源选择、世界选择、任务选择各用独立的 RNG，由 seed 派生。状态写入 `state_dict`，可以精确恢复。
- 来自任务库的回合：通过 `reset(options={"fixed_start_goal": {...}})` 传入起终点和初始偏航，不使用 mid-state 初始化；扰动参数不变。若某个任务没有通过环境自身的 `_candidate_rejection_reasons` 检查，直接报错，不允许静默跳过。
- 配置项：`task_bank.enabled`（默认 false）、`task_bank.path`、`task_bank.sha256`、`task_bank.mixture`、`task_bank.seed`。

### 2.2 任务库文件

- 用 `jindu/2026-10-31_难度分层计算/task_bank.py` 生成，每个世界 400 个随机候选（命令参数 `per_world=400`），生成 seed 为 20261031 加世界序号（脚本已固定）。
- 层级判定规则见分布方案第 3 节；参考实现在本指导附录 A。
- 生成后提交两样东西：任务库 JSON（任务 ID、世界、起点、目标、初始偏航、层级、类型、全部几何指标）和它的 sha256。训练配置里要绑定这个 sha256。
- 交付前核对：每层的任务数、密集世界占比、每个世界每层至少有 1 个任务（没有的层由采样器跳到同类别的其他世界，并在审计中记录）。

### 2.3 reward v3

`reward_version: v3` = v2 的全部项保持不变，另加一项 `risk_close`：

```
c_k = 实际执行路径第 k 个点到最近障碍物的净空（与 v2 相同的障碍几何，不含地面；
      在 reward.py 中对退化线段 [p_k, p_k] 调用 _obstacle_clearances 即可）
碰撞决策中，路径截断到事件点
barrier(c) = clip((1.2 − c) / (1.2 − 0.10), 0, 1) ** 2
risk_close = −4.0 × min( Σ_{k=1..n} max(0, c_{k−1} − c_k) × barrier(c_k), 0.5 )
```

- **含义：** 每个决策中，离障碍物 1.2m 以内时净空减少的量，按接近程度加权。只惩罚靠近障碍物的运动；平行掠过、远离障碍物都不惩罚。依据是 Zhang 2024（接近速度 × 1m 截断二次项，[arXiv:2407.10648](https://arxiv.org/html/2407.10648v2)）和 ClearNav 2026（[arXiv:2610.17419](https://arxiv.org/html/2610.17419)）。
- **参数：** 作用距离 1.2m，约为 RL 后每个决策 0.76m 位移的 1.5 倍；系数 4.0；每个决策最多 −2.0。
- 地面势垒、计划尾段风险、terminal、newbest、time、space 全部不变。
- reward 边界检查要相应更新：`risk_close ∈ [−2, 0]`。
- 审计字段：每个决策的 `risk_close`、`closing_m`（净空减少量）、`min_clearance_m`。

### 2.4 测试与冒烟

1. 单元测试：
   - 默认配置（`task_bank.enabled=false`、`reward_version=v2`）下，P6 配置的第一个外层更新与旧实现逐位一致；
   - 采样器的抽样比例在 10⁵ 次抽样中偏差 < 0.5 个百分点；

- **需要更正一个说法：** 在行为分析报告中，我写过 v2 风险项"预警范围不到一个决策"。实测 v2 风险（包括计划尾段）在碰撞前 3–4 个决策就已经出现。v3 只把预警提前约 1–2 个决策，并让惩罚随接近速度变化。所以 reward v3 的预期作用是中等偏小，本轮的主要变量是任务分布。

## 4. 训练中的监测与停止规则（写死）

- 每 8 轮按层级（L0–L4、原采样器）统计一次训练 rollout 的到达率和碰撞率。注意：第 u 个文件中的 rollout 由第 u−1 轮的策略采集。
- **提前停止：** 改进臂的 L0+L1 训练到达率连续 16 轮比同 seed 对照臂低 15 个百分点以上。对照臂里没有 L0/L1 任务库回合，因此对照臂的数字用它原采样器回合中按同一几何规则判为 L0/L1 的回合来算。
- 受阻层（L2–L4）训练到达率连续 32 轮低于 5% 时，标注"难度过高"，但不调整比例。
- KL、梯度范数门禁沿用原设置。

## 5. 评价与判定（写死）

**评价：** P8–P11 的 @u192，加上 P6@u256 作为参考，都在 dev420 和 val20 上评价，原迹格式与之前一致。**主协议为 #E2（去噪截断 2.0）**，下面的判定规则全部按 #E2 结果执行。不再跑 #E1（v1.2：#E2 已定为统一协议）。**本轮不碰 test12。**

（v1.1 修订，2026-10-31，在任何 P8–P11 运行之前做出：主协议从 #E1 改为 #E2。原因：P6 在 #E2 下 dev420 多了 31 个到达，新增几乎全部来自目标附近；主指标"带内高"在两种协议下基本相同（26 对 28）。用 #E2 可以减少末段到达问题带来的噪声。）

**主指标：** dev420 上，按 `report_outcome_change.md` 中路线带口径分为"带内高"（30 个任务、150 个条件）的到达数和碰撞数。

**判定 F5 有效，需要同时满足以下四条，且两个 seed 对都满足：**
1. 带内高的到达数：F5 ≥ 同 seed 的 F3 + 8（约 5 个百分点）；
2. dev420 总到达数：F5 ≥ 同 seed 的 F3 − 10；
3. 带内无障碍任务相对 P0 的流失数：F5 ≤ 同 seed 的 F3 + 8；
4. val20 总到达数：F5 ≥ 同 seed 的 F3 − 4。

**结论分三种：**
- 两个 seed 对都满足：F5 判定有效，进入完整训练（到 u256）和 test12 评价。
- 只有一个 seed 对满足：判为"不确定"，报告给方案方，不追加 seed 去凑结论。
- 两个都不满足：F5 判定无效。

报告中同时给出 F3 两个 seed 之间的差异（P9 对 P11），作为运行间噪声的参考。

## 附录 A：层级判定（参考实现）

```python
def tier(r):   # r 为 task_bank.py 输出的一行
    if not r['blocked']:
        return 'L0' if r['band_rho'] == 0 else 'L1'
    if r['b_band_m'] is None or (r['path_zmax_m'] or 0) > max(r['start'][2], r['goal'][2]) + 1.0:
        return 'L4'
    if r['kappa'] > 1.0186 or r['b_band_m'] <= 2.30:
        return 'L3'
    return 'L2'
# 世界类别：n_world_obstacles > 8 为密集世界
```
