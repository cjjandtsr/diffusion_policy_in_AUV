## 0. 定位与原则

- **这是工程改进实验，不是根因证明。** 报告中的机制统一作为工作假设。组合臂如果有效，就保留，之后再做消融。
- **三个会影响参数和程序的实际问题，本指引用短程检查来落定，不沿用报告里的数值：**
  1. **漂移门禁：** 5mm/轮的阈值依据不足。本轮只做监测，不启用硬门禁。
  2. **通道掩码会改变更新尺度：** 实现时保持概率比的分母不变，并用首轮梯度检查决定学习率。
  3. **训练加噪后没有严格的 ±1σ 上限：** 垂向检查要统计训练模式下实际执行的动作分布，不能只看截断值。
- **所有新功能都是可选分支，默认值必须与当前行为逐位一致。** 旧 checkpoint、旧配置和旧评价不受影响。
- **对比原则：** 每个改进臂都必须有一个**同父模型、同 seed、同预算的新对照臂**。历史上的 C（182/420）只作参考，不作为判定依据。
- **算力：** 只有一张 RTX 4060，所有 GPU 任务串行。总优先级是：一个改进臂加一个匹配对照，高于更多的诊断或更多的臂。

## 2. T1：有效通道 PPO 分支

### 2.1 语义

- **惰性通道：** 下标 3–8 和 10，即速度、加速度和 yaw rate。它们在轻量环境里不进入位置积分，也不进入观测。
- **为什么只掩最后一个去噪步：** 在中间去噪步，这些通道的中间值会被后续去噪读取，可能影响位置通道的生成，所以默认**只在最后一个去噪步**把它们排除出 PPO。
- 最后一个去噪步对应 `denoising_inds == ft_denoising_steps - 1`，也就是去噪折扣 γ_denoising^0 的那一步。

**为什么不改变更新尺度：** 不是直接删去这些元素，而是把它们的新 logprob 替换成旧 logprob 的 detach 值，平均时分母仍然是 8×11=88。这样做的结果是：
- 被掩元素的 logratio 恒为 0，也不产生梯度；
- 有效元素对概率比的贡献与原实现完全相同，clip 阈值的含义不变。

这样实现，可以把"去掉不利梯度"和"改变比率尺度"这两种效果分开。

### 2.2 配置

```yaml
dppo:
  ppo_inert_mask:
    enabled: false            # 默认为 false，此时与旧实现逐位一致
    channels: [3,4,5,6,7,8,10]
    scope: final_step         # final_step | all_steps（all_steps 只在 C1 中作诊断）
```

### 2.3 修改点

**`rl/dppo_uav_rebuild/engine/official_loss_components.py::compute_official_components`**

新增参数 `inert_mask=None`。在调用 `get_logprobs_subsample` 之后、clamp 之前插入：

```python
if inert_mask is not None and inert_mask.enabled:
    ch = torch.zeros(newlogprobs.shape[-1], dtype=torch.bool, device=newlogprobs.device)
    ch[list(inert_mask.channels)] = True
    if inert_mask.scope == "final_step":
        row = batch.denoising_inds.to(newlogprobs.device) == (runtime.ft_denoising_steps - 1)
    else:
        row = torch.ones_like(batch.denoising_inds, dtype=torch.bool, device=newlogprobs.device)
    m = row[:, None, None] & ch[None, None, :]          # 形状 (B,1,11)，在 H 维上广播
    newlogprobs = torch.where(m, batch.oldlogprobs.detach(), newlogprobs)
```

`slice_diagnostics` 使用替换后的 newlogprobs，这样诊断与实际损失口径一致。

**其他文件：**
- `engine/trainer.py`：`TrainerConfig` 增加 `inert_mask`；`update_logical_batch` 和 `update` 把它透传给 `compute_official_components`。
- `engine/selective_keep.py::calibrate_keep`：同样透传，保证 A2 的标定与训练口径一致。
- `entrypoints/build_system.py`：从 `config.dppo.ppo_inert_mask` 构造。
- `entrypoints/config_schema_v2.py`：允许新键，并校验 channels ⊂ [0,10]、scope 的取值。
- `entrypoints/identity.py`：把这个配置纳入 config_hash（当前已覆盖整个 dppo 段的话，只需核实）。

### 2.4 单元测试（`tests/test_inert_mask.py`）

1. `enabled=false` 时，policy、ratio、梯度与旧实现逐位相同（固定 seed，CPU）。
2. `final_step` 范围下：
   - `denoising_inds < 9` 的 pair，ratio 逐位不变；
   - `= 9` 的 pair，ratio 等于"只用有效通道计算的 logratio 之和除以 88"再取 exp。
3. 惰性通道的 x0 输出对 policy loss 的梯度：最后一步为 0，其余步非 0（用一个小型假 actor 验证）。
4. 真实 E5PPODiffusion 构造的冒烟测试，参照 A2 v1.2 的做法，防止测试替身漏掉真实接口的问题。

## 3. T2：动作漂移监测（只记录，不门禁）

### 3.1 探针库

- **来源：** 在 fork 后第一个外层更新（u129）的 rollout 中，按 task.role 分层，抽取 256 个转移的 actor 条件（`state`、`global_cond`）。
- **固定内容：** 每个探针绑定一个初噪种子。
- **保存：** 写入结果目录 `drift_probe_bank.pt`，记录 sha256，并在 checkpoint 中保存 bank 的 hash。resume 时校验，不重新抽样。
- **复用：** X 与 K 两臂必须使用**同一个**探针库。因为两臂同 seed，u129 的 rollout 相同，各自生成的探针库应当逐位一致，以此作为门禁检查；也可以先生成一次，再让两臂都加载。

### 3.2 度量

确定性 DDIM（`deterministic=True`）采样，取：
- H4 位置：`full[:, 2:6, 0:3]` 的累加；
- 惰性通道：`full[:, 2:10, [3..8,10]]`。

在两个时点计算：
- **(a) 每个外层更新的开始与结束：** 记录 `step_h4_rms_m`（256 个探针的 H4 端点 RMS 变化，单位米）和 `step_inert_norm`（惰性通道 |Δ|/σ_demo 的均值，σ 取自 normalizer 的 input_stats.std）；
- **(b) 相对 fork 起点（u128）的累计值：** `cum_h4_rms_m`、`cum_inert_norm`。

另外，每 5 次提交测一次 (a)，写入 `drift_monitor.intra[]`，用于看外层更新内部的漂移是否均匀。

### 3.3 修改点

- **`entrypoints/pipeline.py`：** 在外层循环中，`buffer.finalize()` 之后、提交循环之前取参考值；提交循环里每 5 次检查一次；`outer_parameter_delta` 之后取终值。结果写入 metrics 的顶层 `drift_monitor`。
  - 不改变任何参数更新，不改变 RNG 流。采样使用 `torch.random.fork_rng`，参照 `calibrate_keep` 的写法。
- **新增 `engine/drift_monitor.py`：** 包含建库、度量、序列化三部分。

### 3.4 单元测试

- 启用和不启用监测时，训练参数、Adam 状态、全局 RNG 状态逐位相同。
- 探针库在 resume 前后 hash 一致。
- 参数不变时，度量为 0。

### 3.5 门禁的落定方式（不在本轮启用）

- 本轮只收集数据。K 臂的 `step_h4_rms_m` 分布作为"健康续训"的实测基准。
- R1 结束后，如果 X 或 K 的流失集中出现在某个 `step_h4_rms_m` 异常段，再以 K 臂分布的高分位（例如 p99 的 2 倍）作为下一轮门禁的候选阈值。
- 门禁的实现预留接口 `dppo.drift_gate.enabled=false`，本轮不实现跳过提交的逻辑。

## 4. T3：按通道的噪声下限与截断范围参数化

### 4.1 vendor 与 runtime 修改

**`third_party/dppo_official_cc7234a/model/diffusion/diffusion_vpg.py`**
- 采样：第 325 行 `std = torch.clip(std, min=min_sampling_denoising_std)`；
- logprob：第 428 行与 `get_logprobs_subsample` 中第 493 行的 `std = torch.clip(std, min=self.min_logprob_denoising_std)`。

三处统一改为：
```python
std = torch.maximum(std, _as_floor(self.<对应下限>, std))   # _as_floor：标量或形状 (11,) 的张量，在 (B,16,11) 上广播
```
`get_min_sampling_denoising_std()` 在标量时返回标量，在向量时返回 buffer。

**`third_party/dppo_official_cc7234a/uav_idp3/e5_runtime.py`**
- `min_sampling_denoising_std` 和 `min_logprob_denoising_std` 接受 float 或长度为 11 的序列。向量形式注册为 buffer，并且必须与 action_dim 一致。
- 新增 `denoised_clip_override: Optional[float] = None`：
  - 为 None 时，保持现有逻辑（读取原生调度器的值，并拒绝不一致的传入）；
  - 非 None 时，使用该值，并写入 `self.clip_protocol = {"native": 1.0, "override": v}`。
- 两项都纳入 runtime identity 的内容哈希。

**`entrypoints/build_system.py`：** 从 `config.dppo.min_std_vector`（可选，长度 11）和 `config.dppo.denoised_clip_value`（可选）读取。**采样下限与 logprob 下限必须使用同一个向量**，构造时用断言保证。

**`scripts/evaluate_dppo_uav_formal_endpoint.py`：**
- 增加 `--denoised-clip-value`、`--min-std-vector`（逗号分隔的 11 个数）、`--sampling-mode {deterministic,random}`；
- 写入评价元数据和身份；
- 默认值与当前行为一致。

### 4.2 单元测试

- 标量 0.1 与向量 `[0.1]*11` 的采样链、logprob 逐位相同。
- 向量下限下，只有对应通道的 std 被抬高；采样和 logprob 使用同一下限。
- clip 覆盖为 None 时与现状逐位一致；覆盖为 2.0 时，x_recon 被截断到 ±2。
- vendor 文件的 SHA256SUMS 与身份闭包更新后，旧 checkpoint 的加载路径仍然可用：旧身份只在旧源码快照下复现，新身份走 fork。

### 4.3 注意

- 训练模式下，最后一步的噪声加在截断之后，执行动作可以超出截断值。C2 必须统计实际执行动作的归一化分布，而不是只看截断值。
- 截断范围只要改了，**BC 和对照臂也必须用同一个值评价**，否则比较不公平。

## 5. T4：惰性通道 BC 锚定（可选，默认关闭）

**目的：** PX4 部署会使用通道 3–8 和 10，要防止这些通道随训练漂移，造成部署时不一致。

**实现：** 在 `trainer.update_logical_batch` 中照搬 keep 分支的梯度合并路径。
- 样本：在当前逻辑批的 pair 上抽取 128 个 (condition, chains_prev, denoising_ind)；
- 计算 actor_ft 与 base（`use_base_policy=True`，no_grad）的 x0 预测，只取通道 3–8 和 10、H 索引 2:10，计算 MSE；
- 系数用 `calibrate_keep` 同样的方法一次性标定，`target_ratio=0.05`，结果写入 `inert_anchor_calibration.json`；
- 状态和 RNG 写入 checkpoint 的 schedules。

**本轮怎么用：** R1 默认关闭，只用 T2 的 `cum_inert_norm` 记录这些通道的漂移。
- 如果 X 臂的 `cum_inert_norm` 明显高于 K 臂（例如超过 1.5 倍），部署验证之前必须启用锚定，再续训或重训；
- 如果不高于 K 臂，就留待部署对照（开前馈和关前馈）来决定。

**单元测试：** 系数为 0 时逐位不变；锚定梯度只作用于 actor；resume 往返一致。

## 6. C1：更新改进的短程检查（约 2h GPU）

**设置：**
- 从 B2560 u128 用显式 fork 分叉（复用 `checkpointing/a2_fork.py` 的父子身份流程），两臂使用同一个新 seed `s1`；
- 各跑 **8 个外层更新**（u129–u136，约 47 分钟一臂）：
  - K8：现状配置；
  - X8：`ppo_inert_mask.enabled=true, scope=final_step`；
- 两臂都开启 T2 监测。

**首轮门禁（u129，两臂同一 rollout）：**
- rollout、raw GAE、pair 排列逐位一致，以证明两臂的差异只来自损失；
- 记录第一个逻辑批的：actor 梯度范数比 X/K、两者梯度的余弦、最后去噪步的 logratio 分位数、clip_fraction。

**检查项与落定规则：**

| 检查 | 规则 |
|---|---|
| 梯度范数比 X/K（u129 共 20 个逻辑批的中位数） | 在 [0.7, 1.4] 内：学习率不变。<0.7：学习率不调高，记为"有效步长变小"，R1 照常进行，解释时注明。>1.4：actor_lr 乘以中位比的倒数，只调这一次 |
| clip_fraction 与 approx_kl（u129–u136） | 默认 clip 保持 0.1。只有当 X8 的 `step_h4_rms_m` 中位数超过 K8 的 2 倍时，才把 clip 收紧到 0.05 |
| `step_h4_rms_m`、`step_inert_norm` 曲线 | 只记录，作为 R1 的预期范围 |
| 硬故障 | 出现 NaN、拒绝提交，或 X8 的 8 轮训练到达率比 K8 低 15 个百分点以上：停止，回传现场 |

**附加诊断（可选，约 10 分钟）：** 在 u129 的同一批数据上，计算 `scope=all_steps` 的梯度范数比和余弦。只记录，不进入 R1。

C1 的 8 轮结果**不作为能力判断依据**，只用来定参数和排除故障。

## 7. C2：垂向探索的离线检查（约 2–3h GPU）

### 7.1 状态库

从 A2 dev 原迹（`jindu/routea_a2_selective_keep_run01/full/`）中筛选：

- **V 组（目标下方停滞）：** 策略为 u128、C、T 的超时回合，满足以下条件，且当前决策前位置距目标 <2m、低于目标 >0.3m：
  - 路径上离目标最近的点距离 <1m；
  - 该点比目标低超过 0.3m。

  按任务去重，最多 40 个状态，每个任务最多 3 个。
- **S 组（安全对照）：** 策略 C 的成功回合中，当前位置离障碍连续间隙 <0.6m 的决策状态，按任务去重，最多 40 个。
- **重建观测：** 复用统一评价入口的 recovery bank 构造方法，即三帧观测哈希重建，冻结后记录 bank hash。

### 7.2 采样矩阵

- **策略：** C（u256）和冻结的 u128。BC 只在 clip 变体下做参考。
- **模式：** random（训练模式），每个状态 50 次，初噪按 `paired_seed(state, draw)` 配对。
- **变体（6 组）：** z 下限 ∈ {0.1, 0.3, 0.6} × 截断 ∈ {1.0, 2.0}。其余通道下限保持 0.1；yaw 不改。
- **补充：** 截断为 2.0 时，额外做一组 deterministic 模式，看评价行为的变化。

### 7.3 指标

**V 组：**
- H4 执行段（实际连续线段）首次进入 0.5m 目标球的比例；
- H8 计划进入目标球的比例；
- H4 的 Δz 分布；
- 实际执行动作的归一化 Δz 超过 1 的比例。

**S 组：**
- H4 与 H8 的碰撞比例；
- 最小间隙的分布。

### 7.4 选择规则

先对每个变体计算，再挑选：

1. **安全约束：** S 组 H8 碰撞比例比基线（0.1 / 1.0）的增加不超过 2 个百分点。
2. 在满足安全约束的变体中，选 V 组 **H4 入球比例**最高的一个。只有当它比基线高出至少 5 个百分点（绝对值）时，才进入 R1。
3. **同分时**，优先保持截断为 1.0（改动更少，也不需要重新确立 BC 基线）。
4. **如果没有变体满足第 2 条，** R1 只带 T1 一项改动，在记录中写明"垂向探索候选未通过离线检查"。

**说明：** 选出 z 下限与截断之后，**sampling 和 logprob 使用同一个向量**。截断改为 2.0 的话，E1 中所有策略（包括 BC 和 K）都按 2.0 评价，并另外报告 1.0 下的结果作对照。

## 8. R1：匹配训练

**父模型：** B2560 u128，显式 fork。

| 臂 | 内容 | seed |
|---|---|---|
| **K**（匹配对照） | 现状配置，开启 T2 监测 | s2 |
| **X**（改进臂） | T1（scope=final_step）＋ C2 选出的 T3 设置（如有）＋ C1 定下的学习率与 clip，开启 T2 监测；T4 关闭 | s2 |

**通用设置：**
- 两臂都按 C 的设置运行：2560/20、actor_lr 2e-5→1e-5、128 个外层更新到全局 u256，λ=0；reward 和环境不变。
- checkpoint 每 8 轮保存一次。
- 先运行 X，再运行 K。如果 X 出现硬故障，K 照样运行，因为对照臂本身也提供运行噪声的数据。

**首轮门禁：** 两臂 u129 的 rollout、raw GAE、pair 排列逐位一致。如果 X 改了截断或噪声下限，rollout 自然不同，此时只核对父状态恢复和 RNG 起点一致。

**运行中只停硬故障：** NaN、拒绝提交、身份不符、门禁失败。普通的训练到达率波动不停，也不中途改预算。

**每臂回传：**
- 全部 metrics、`drift_monitor`、探针库 hash；
- C1/C2 的选择记录；
- checkpoint 身份。

## 9. E1：评价与判定

**评价（统一入口）：**
- dev 420：BC、u128、K-u256、X-u256；
- val20：K 和 X 的 u160、u192、u224、u256，用来看趋势和做选点参考。

| 类别 | 指标 |
|---|---|

**判定：**

| 结果 | 结论与下一步 |
|---|---|
