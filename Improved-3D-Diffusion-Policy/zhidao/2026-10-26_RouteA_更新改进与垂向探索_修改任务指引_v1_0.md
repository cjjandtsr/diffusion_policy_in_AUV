## 2. T1：有效通道 PPO

### 2.1 语义

- **惰性通道：** 下标 3–8 和 10。
- **只在最后一个去噪步掩码**，即 `denoising_inds == ft_denoising_steps - 1`，对应去噪折扣 γ^0 的那一步。在中间去噪步，这些通道仍可能影响后续位置通道的生成，所以保留。
- **实现方式：** 把被掩元素的新 logprob 替换为对应旧 logprob 的 detach 值，求均值时分母仍为 8×11=88。
- **效果：** 被掩元素的 logratio 恒为 0，不产生梯度；有效元素对概率比的贡献与原实现相同，clip 的含义不变。

### 2.2 配置

```yaml
dppo:
  ppo_inert_mask:
    enabled: false                 # 默认关闭，与旧实现逐位一致
    channels: [3,4,5,6,7,8,10]
    scope: final_step              # final_step | all_steps（all_steps 只用于 C1 诊断）
```

### 2.3 修改点

`rl/dppo_uav_rebuild/engine/official_loss_components.py::compute_official_components`：新增参数 `inert_mask=None`，在 `get_logprobs_subsample` 之后、clamp 之前插入：

```python
if inert_mask is not None and inert_mask.enabled:
    ch = torch.zeros(newlogprobs.shape[-1], dtype=torch.bool, device=newlogprobs.device)
    ch[list(inert_mask.channels)] = True
    if inert_mask.scope == "final_step":
        row = batch.denoising_inds.to(newlogprobs.device) == (runtime.ft_denoising_steps - 1)
    else:
        row = torch.ones_like(batch.denoising_inds, dtype=torch.bool, device=newlogprobs.device)
    m = row[:, None, None] & ch[None, None, :]
    newlogprobs = torch.where(m, batch.oldlogprobs.detach(), newlogprobs)
```

`slice_diagnostics` 使用替换后的值。同时修改以下位置，透传或校验该配置：
- `engine/trainer.py`：`TrainerConfig`、`update` 和 `update_logical_batch` 透传；
- `engine/selective_keep.py::calibrate_keep`：透传；
- `entrypoints/build_system.py`：从配置构造；
- `entrypoints/config_schema_v2.py`：允许新键并校验；
- `entrypoints/identity.py`：确认该配置已进入 config_hash。

### 2.4 测试（`tests/test_inert_mask.py`）

1. `enabled=false` 时，policy、ratio、梯度与旧实现逐位相同。
2. `final_step` 时：非末步 pair 的 ratio 不变；末步 pair 的 ratio 等于 exp(有效元素的 logratio 之和 / 88)。
3. 用小型假 actor 验证：惰性通道上的输出，在末步的梯度为 0，在其余步非 0。
4. 构造真实的 E5PPODiffusion 做冒烟测试，防止测试替身遗漏真实接口的问题（参照 A2 v1.2 的教训）。

## 3. T2：动作漂移监测（只记录）

### 3.1 探针库（两臂共用，只生成一次）

- **来源：** 父 checkpoint u128 的 `state.pt` 中保存的 `rollout_buffer`（u128 那一轮采集到的数据），只读提取其中 actor 条件的 `state` 和 `global_cond`。
- 按 role 分层抽取 256 个状态，每个状态绑定一个固定的初噪种子。
- 写入 `drift_probe_bank_v1.pt`，记录 sha256。X 和 K 两臂都加载这一份，checkpoint 里保存它的 hash，resume 时校验。
- 采样协议固定为 deterministic=True，并使用**原协议**（截断 1.0、噪声下限 0.1），与各臂训练时用的协议无关。这样两臂的漂移度量可以直接比较。

### 3.2 度量

- **H4 位置：** `full[:, 2:6, 0:3]` 累加得到 H4 端点。
- **惰性通道：** `full[:, 2:10, [3..8,10]]` 按 |Δ|/σ_demo 计，σ 取 normalizer 中的 input_stats.std。

**记录内容：**
- 每个外层更新开始和结束时：`step_h4_rms_m`、`step_inert_norm`；
- 相对 u128 的累计值：`cum_h4_rms_m`、`cum_inert_norm`；
- 外层更新内部，每 5 次提交记录一次，写入 `drift_monitor.intra[]`。

### 3.3 修改点

- **`entrypoints/pipeline.py`：** 在 `buffer.finalize()` 之后取参考值，在提交循环中按间隔测量，在 `outer_parameter_delta` 之后取终值，结果写入 metrics 的 `drift_monitor`。采样包在 `torch.random.fork_rng` 里，不改变训练用的随机数流。
- **新增 `engine/drift_monitor.py`。** 预留 `dppo.drift_gate.enabled=false`，本轮不实现跳过提交的逻辑。

### 3.4 测试

- 开启和关闭监测时，参数、Adam 状态、全局 RNG 逐位相同。
- 探针库在 resume 前后的 hash 一致。
- 参数不变时，度量结果为 0。

### 3.5 用途

R1 结束后，以 K 臂实测的漂移分布（例如 p99 的 2 倍）作为下一轮门禁阈值的候选。监测数据本身不作为好坏的判据。

## 4. T3：按通道的噪声下限与截断覆盖

### 4.1 修改点

**`third_party/dppo_official_cc7234a/model/diffusion/diffusion_vpg.py`：** 共三处——采样处第 325 行，以及 logprob 处第 428 行和 `get_logprobs_subsample` 中的第 493 行。原写法 `torch.clip(std, min=<下限>)` 统一改为 `torch.maximum(std, _as_floor(<下限>, std))`，同时支持标量和形状为 (11,) 的下限。

**`third_party/dppo_official_cc7234a/uav_idp3/e5_runtime.py`：**
- `min_sampling_denoising_std` 和 `min_logprob_denoising_std` 接受标量或 11 维序列；向量形式注册为 buffer。
- 新增 `denoised_clip_override: Optional[float]=None`：
  - None 时，保持现有逻辑：读取原生调度器的值，并拒绝不一致的传入；
  - 非 None 时，使用该值，并记录 `clip_protocol={"native":1.0,"override":v}`。
- 以上两项都进入 runtime identity。

**`entrypoints/build_system.py`：**
- 读取 `dppo.min_std_vector` 和 `dppo.denoised_clip_value`；
- 采样与 logprob 必须使用同一个下限向量，用断言保证。

**`scripts/evaluate_dppo_uav_formal_endpoint.py`：**
- 新增 `--denoised-clip-value`、`--min-std-vector`、`--sampling-mode`，默认值与现状一致；
- 这些参数写入评价元数据和身份。

### 4.2 测试

- 标量 0.1 与 `[0.1]*11` 的采样链和 logprob 逐位相同。
- 使用向量下限时，只有对应通道的 std 被抬高，采样与 logprob 一致。
- 截断覆盖为 None 时与现状逐位一致；为 2.0 时，x_recon 被截断在 ±2。
- 旧身份只在旧源码快照下复现，新身份走 fork。

### 4.3 说明

- 训练采样在截断之后还会再加噪，所以执行的动作可以超出截断值。C2 统计的是实际执行的动作分布。
- 截断经过 vendor 时，是先用未截断的 x0 推出 ε 再截断，所以中间步仍有梯度路径。改动截断范围就是一种新的采样协议，必须与原协议分开报告（见第 10 节）。

## 5. T4：惰性通道锚定（实现，不启用）

**做法：** 照搬 `trainer.update_logical_batch` 中 keep 分支的梯度合并路径。
- 对当前逻辑批中 128 个 pair，计算 actor_ft 与 base（`use_base_policy=True`，no_grad）输出的 x0，只取通道 3–8 和 10、H 索引 2:10，计算 MSE。
- 系数按 `calibrate_keep` 的方法一次性标定，`target_ratio=0.05`。
- 状态和 RNG 写入 schedules。

**测试：** 系数为 0 时逐位不变；梯度只作用于 actor；resume 往返一致。

**R1 中不启用。** 如果 X 的 `cum_inert_norm` 超过 K 的 1.5 倍，触发**部署接口核查**：在 PX4/Gazebo 链路上，对比开启前馈和关闭前馈两种情况下的实际执行输出。是否启用锚定由核查结果决定。启用后得到的是新模型，必须重新评价。

## 6. T5：自模仿保持（可选，默认不纳入 X，需用户确认）

**动机：**
- A2 的 T 证明保持项能防止已有成功流失：BC 原本 5/5 成功的任务，T 保住 100/105，C 是 85/105。
- 但 T 的参考库固定为 BC 和 u128 的行为，压低了新增：两者都失败的类别，T 新增 23，C 新增 51。
- 自模仿把当前策略自己的成功也加入参考库，目标是保持与新增兼顾。
- 这是目前唯一有干预证据支持的杠杆的改进版本。

**设计：**
- **来源：** 每个外层更新的 rollout 中，到达回合内的所有转移。在 buffer 中按连续的 transition 片段回溯标记，片段以终止、截断或采集边界为界。取 actor 条件，以及 `chain[-1]`（归一化后的最终 x0，16×11）。
- **监督范围：** 与 A2 相同，执行权重只覆盖 H4 `[2:6]` 中的通道 `[0,1,2,9]`。末段按执行分数进行加权。
- **库的构成：**
  - 滚动库，保留最近 8 个外层更新的成功前缀，上限 2048 条；
  - 初始化时加入 A2 的参考库，即 549 条 BC/u128 前缀，按时间逐步被替换。
- **损失：** 复用 `SelectiveKeep.loss` 的 x0 MSE 形式（DDIM 位置配对，即 v1.2 修复后的写法）。
- **系数：** 在 u129 上按 `calibrate_keep` 的方法一次性标定，`target_ratio=0.1`，与 T 保持可比。之后不在线调整。
- **状态：** 库内容的 hash 和 RNG 写入 checkpoint，resume 时校验。

**风险：** 自模仿可能放大当前策略的偏差，并降低探索。纳入 X 后，T5 的贡献无法单独分离，需要在 10-31 之后做消融。

**测试：**
- 系数为 0 时逐位不变；
- 到达回合内转移的标记正确，包括跨越采集边界的情况；
- 库的滚动与 resume 一致；
- 用真实 E5 runtime 做冒烟测试。

## 7. C1：更新改进检查

### 7.1 冻结父状态上的梯度比较（不提交，约 20 分钟）

- 从 u128 fork（参照 `checkpointing/a2_fork.py`），用 seed s2 采集一轮 u129 的 rollout。
- 在同一组参数（u128）和同一个 buffer 上，对 20 个逻辑批分别计算以下梯度，全程**不做优化器步进**：
  - 掩码关闭；
  - 掩码开启（`final_step`）；
  - 诊断用：`all_steps`。
- 记录：actor 梯度范数比 X/K、两者的余弦、末步 logratio 的分位数。

**学习率规则（只做一次）：**
- 20 批梯度范数比的中位数在 [0.7, 1.4] 内：学习率不变；
- 大于 1.4：`actor_lr` 乘以中位比值的倒数；
- 小于 0.7：学习率不变，并记录"有效步长偏小"。

### 7.2 短程运行（各 8 轮，约 1.5 小时，只用于查故障和看漂移曲线）

- X8 和 K8 都从 u128 出发，各跑 u129–u136，开启 T2 监测。
- **首轮门禁：** 两臂 u129 的 rollout、raw GAE、pair 排列逐位一致。如果 X 带有 T3 设置，则只核对父状态恢复和 RNG 起点。
- **clip 规则：** 默认保持 0.1。只有当 X8 的 `step_h4_rms_m` 中位数超过 K8 的 2 倍时，才收紧到 0.05。
- **只在工程故障时停止：** NaN、拒绝提交、身份不符、门禁失败。到达率不作为停止依据，也不作为能力判断的依据。

## 8. C2：垂向采样的闭环检查

**定位：** 只针对"停在目标下方"这一种失败。C2 不通过，X 就不纳入 T3，也不扩大参数搜索。

### 8.1 状态库（冻结 hash）

| 组 | 来源 | 选取条件 | 数量 |
|---|---|---|---|
| **V 组（目标下方停滞）** | A2 dev 原迹中 u128、C、T 的超时回合 | 离目标最近的点距离 <1m 且低于目标 >0.3m；取当前决策前、距目标 <2m 且低于目标 >0.3m 的状态 | 40 个，按任务去重，每个任务最多 3 个 |
| **P 组（成功正对照）** | C 的成功回合 | 其中 10 个是离障碍连续间隙 <0.6m 的状态，另 10 个是一般的接近段状态 | 20 个 |

用统一评价入口中 recovery bank 的方法重建三帧观测。

### 8.2 矩阵与预算

- **策略：** 只用 C；时间允许时再补 u128。
- **采样变体（4 个，不做交叉组合）：**
  - 基线：截断 1.0，z 下限 0.1；
  - z 下限 0.3；
  - z 下限 0.6；
  - 截断 2.0。
- **采样模式：** random，与训练一致。每个状态续飞 5 次，初噪按 `paired_seed(state, draw)` 配对。
- **续飞规则：** 复用 recovery 续飞，每次最多 12 个周期，保留原任务剩余期限。
- **规模：** 60×4×5 = 1200 次续飞。按 10-22 实测约 3 秒/次估计约 1 小时。先跑一个变体测实际耗时，超过 2 小时就把每个状态的续飞次数降到 3。

### 8.3 结局记录

- **到达：** 实际执行路径首次进入 0.5m 目标球；
- **碰撞；**
- **`window_end`：** 12 个周期用完仍未到达；
- **超时：** 只有在用完原任务剩余期限时才记。

此外统计实际执行动作的归一化 Δz 分布，以及超过 1 的比例。

### 8.4 选择规则（预先固定）

1. **安全：** P 组碰撞比例比基线增加 ≤2 个百分点；同时在不将 window_end 计为失败的口径下，P 组到达比例不比基线低超过 5 个百分点。
2. **收益：** 在满足第 1 条的变体中，选 V 组到达比例最高的。只有比基线高出 ≥5 个百分点（绝对值）才采用。
3. 若有并列，优先选截断保持 1.0 的变体。
4. 没有变体满足条件时，X 不纳入 T3。

- val20：K 和 X 的 u192、u256，用于看趋势，不用于选点。

**如果 X 改了截断，分两层报告：**
- **原协议（截断 1.0）：** BC、u128、K、X 都按 1.0 评价。这一层衡量训练更新带来的收益。
- **共同新协议（截断 2.0）：** BC、K、X 都按 2.0 评价。这一层衡量推理配置带来的收益。

**预先登记的指标（以 X−K 配对差为主）：**

| 类别 | 指标 |
|---|---|
| 主指标 | 安全到达；碰撞 |
| 保持 | u128 成功条件中保住的数量；BC 成功条件中保住的数量 |
| 新增 | 目标 ≥3m 的新增成功；u128 与 BC 都失败类别中的新增 |
| 分层 | 目标 <3m 的受阻组和通畅组（受阻按既有判据：`segment_obstacle_collision(...,0.1)`）；目标 ≥3m 组和 ≥3.5m 组 |
| 机制观察 | 停在目标下方的超时数；`cum_h4_rms_m`；`cum_inert_norm` |
| 统计 | 以 21 个世界为簇的 bootstrap 区间（20000 次，固定种子）；任务级的保住、丢失、新增 |

**判定规则：**

| 结果 | 结论 |
|---|---|
| X 到达 > K，聚类区间不含 0，且碰撞 ≤ K+5 | 组合有效，保留 X，安排消融和复现 |
| X 与 K 的差距在区间之内 | 本轮测不出差别。如果保住数或碰撞明显更好，就记为"保持或安全方面的候选" |
| X 到达 < K，或碰撞 > K+10 | 不采用，用监测数据定位原因 |
| X 的 `cum_inert_norm` > 1.5 × K | 触发部署接口核查（第 5 节） |

**K 与 C 的比较：** 单独报告，作为同一设置下运行波动的描述，不用于判定 X。
