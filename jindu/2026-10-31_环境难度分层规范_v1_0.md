# iDP3-UAV RL 后训练：环境难度分层规范 v1.0

日期：2026-10-31。状态：用户已确认方案，此后所有评价报告都按本规范分层。策略编号见 `jindu/2026-10-31_策略编号规范_v1_0.md`。

## 0. 目的与原则

- **目的：** 按环境本身的难度，把每个策略和 P0（BC 基线）在相同任务上逐条配对比较，看清 RL 在哪类环境上有收益、在哪类上有流失。
- **原则：**
  1. **分层只用环境信息：** 起点、终点、障碍物几何。不使用任何策略的结局，包括 P0 的结局。
  2. **先定档，后看结果：** 本文第 3–5 节的全部参数和分档边界，在把任何策略结局接进分层之前固定，并登记在本文第 8 节。
  3. **分档以任务为单位：** 同一任务的 5 次重复几何相同，属于同一档。

## 3. 走廊密度（主维度）

**走廊几何（以起终点连线为中心轴的长方体）：**
- 记起点 S、终点 G。水平轴向单位向量 û = (G−S) 在水平面上的投影方向；水平横向单位向量 v̂ ⊥ û。
- 一个点 p 在走廊内，当且仅当同时满足：
  - 轴向：p 在 û 上相对 S 的投影 t ∈ [0, L]，L = |G−S| 的水平长度（两端不外延）；
  - 横向：|(p−S)·v̂| ≤ w，w 为半宽，**主口径 w=1.0m，敏感性 w=2.0m**；
  - 竖向：z ∈ [min(z_S, z_G) − 1.0, max(z_S, z_G) + 1.0]，下限不低于 0.2m（触地高度）。
- 退化情况：水平长度 L < 0.5m 时，走廊改为以 S、G 中点为中心、半径 w 的竖直圆柱。出现时在报告中列出。

**指标：**
- **走廊密度 ρ_w** = 走廊内被障碍物占据的体积 ÷ 走廊总体积。障碍物按原始几何（圆柱 / 带偏航的长方体），不膨胀。
- 计算方法：在走廊内取 0.05m 规则网格点，统计落在任一障碍物内的比例。
- 同时记录：与走廊相交的障碍物个数 n_w。只记录，不分档。

**分档：**
- 在全部 132 个任务（dev 84 + test12 48）上，按 ρ_1.0 的三分位分为低、中、高三档。
- 如果 ρ_1.0 = 0 的任务占三分之一以上：ρ=0 单独成"无障碍"档，其余任务按中位数分为"低""高"两档。
- w=2.0m 用同样规则单独分档，只用于敏感性检查。

## 4. 最窄通道（附表一）（v1.1 修订）

**定义：** 在"直达路线带"内，从 S 到 G 的所有无碰撞路径中，路径上离障碍物最近距离的最大值，记为 b_band，单位 m。它表示：沿直达方向、不大幅爬升、也不远离直线时，无人机至少要穿过多窄的空隙。对应 BARN 的 characteristic dimension 和 FlightBench 的可通行受阻度。

**直达路线带：**
- 水平方向：离 S–G 水平连线的横向距离 ≤ 3.0m；轴向从 S 前 1.0m 到 G 后 1.0m。
- 竖向：z ∈ [0.2, max(z_S, z_G) + 1.0]。

**计算：**
- 栅格：分辨率 0.1m，空间范围是 S、G 和全部障碍物的外包盒四周外扩 3m，竖向 [0.2, 6.0]。
- 净空：用栅格欧氏距离变换，取空闲栅格中心到最近障碍栅格中心的距离，再减去半个栅格；地面 z=0.2 也算障碍。障碍按原始几何，不膨胀。
- **端点球：** S、G 周围 1.0m 内的空闲栅格一律视为可通过，不计入瓶颈。否则 b 主要由起终点离障碍物多近决定，而不是途中通道的宽窄。
- 路径：26 邻接。对阈值 r 二分查找（容差 0.01m），找到使 S、G 在"净空 ≥ r 的栅格 ∪ 端点球"中仍然连通的最大 r。
- S 与 G 在带内不连通时，记为"带内不可达"，单独成一档。

**修订原因（v1.0 → v1.1，在接入任何策略结局之前做出）：** v1.0 的定义是在整个空间里求 max-min 路径，不加端点球。实算发现它没有区分度：b 的范围是 1.77–5.75m，和走廊密度的 Spearman 相关只有 −0.18。原因是最优路径总能爬到障碍物顶部之上（障碍物顶高 3.0–6.8m，空间上限 6.0m），或者绕到整个障碍群外面，所以 b 反映的是开阔空间的大小，不是通道的宽窄。v1.0 的值仍然保存在 `task_metrics.json` 的 `b_m` 字段里，但不再使用。

**分档：** 对带内可达的任务，按 b_band 的三分位分为窄、中、宽三档；"带内不可达"单独一档。

## 5. 绕行需求（附表二）

**定义：** 无碰撞最短路径长度 ÷ 起终点直线距离，记为 κ。另记路径累计转角 θ_sum（弧度），只报告，不分档。

**计算：**
- 空间范围和栅格同第 4 节。
- 障碍物按现有碰撞判据膨胀：水平 0.1m（与 `segment_obstacle_collision` 的阈值一致），竖向 0.1m（`DRONE_RADIUS_Z`）。
- 用 26 邻接 A* 求最短路径，再用视线捷径平滑：连续节点之间如果 `segment_obstacle_collision(a, b, obstacles, 0.1)` 返回 None，就直接连通。平滑后的折线计算 κ 和 θ_sum。
- **不使用环境里现有的 `_astar_3d`**（`kinematic_uav_env.py` 第 644 行）。它是 0.5m 栅格、6 邻接，返回的瓶颈值固定为 1.0，用来量化难度不够准确。

**分档：** 先单列直线通畅的任务（κ=1），作为"无需绕行"档。其余可达任务按 κ 的中位数分为"小绕行""大绕行"两档。

**v1.1 注：** 最短路径可以从障碍物顶部飞过。实算中 κ 最大只有 1.092；有 12 个任务的最短路径升到 4.5m 以上，比如两堵 5m 高的墙横在直线上时，最短路径从墙顶飞过。这种情况下 κ 会低估难度，因为它不考虑需要爬升到示范高度带之外。报告时同时给出路径最高点 `path_zmax_m`。

## 6. 辅助标记

- **直线是否受阻：** `segment_obstacle_collision(S, G, obstacles, 0.1)` 返回非 None 即为受阻。它只说明直线会不会撞，不衡量难度。
- **P0 表现档：** P0 在该任务 5 次重复中的成功次数，分 0/5、1–4/5、5/5 三档。它反映"对 BC 难不难"，不是环境难度，也不参与环境分档。用途是在报告里区分"新增"（P0 失败、策略成功）和"流失"（P0 成功、策略失败）主要发生在哪里。

## 7. 报告格式

每个评价集（dev420、val20、test12）、每个维度各出一张表：

| 列 | 内容 |
|---|---|
| 档 | 档名和数值区间 |
| 任务数 / 条件数 / 世界数 | — |
| 各策略到达数 | 包括 P0 |
| 相对 P0 的新增 / 流失 | 逐条配对 |
| 差值和 95% CI | 按世界聚类 bootstrap，20000 次，seed 2026102601。档内世界数少于 5 时只报计数，不报 CI |

另外必须附：
- 同方法运行之间的差异（P3、P4、P5）在同一档的范围，作为噪声参考；
- 每档的碰撞数和超时数。

判读规则：
- 不比较一档内的净值，比较的是新增和流失各自的数量；
- 不同策略在同一档内比较；
- test12 的分层结果只算描述性结果。

3. 每个维度每档各抽 3 个任务，画俯视图和侧视图：障碍物、走廊、最短路径、瓶颈点。抽样 seed 20261031。
