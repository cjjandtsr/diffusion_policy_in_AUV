## 1. 项目目标与约束（用户确定，不变）

- **目标：** 以扩散策略 BC 为起点做 RL 后训练，安全到达率要有较大提升，并且在下面三项能力中至少改善一项：提前避障、扩大 x/y/z 空间支持、密集障碍中的绕行/脱困/恢复。用户的本质诉求是"提高到达成功率，并找出越训越差的原因、加以解决"。
- **主终点：** 实际执行的 H4 连续路径，在碰撞之前首次进入半径 0.5m 的目标球。
- **约束：** 扩散策略保持核心地位；不使用策略外的裁剪或修正来制造成功；EGO 示范数据冻结；评价用的世界不进入训练。
  - **2026-10-30 修订（用户确认）：** 允许"扩散策略导航 + 目标附近切换直线控制器完成末段"的分层架构。策略本身到达率仍是 RL 后训练的主终点；系统到达率（策略 + 末段引导）单独报告，两者不混用。先做离线上限统计，见 `Improved-3D-Diffusion-Policy/zhidao/2026-10-30_末段直线引导_离线上限统计_执行指导_v1_0.md`。

- **时间节点：** 2026-10-31。
- **算力：** 一张本地 RTX 4060（WSL），所有 GPU 任务只能串行。
- **执行方式：** 本对话（Kiro）负责分析、写文档、做离线统计，可以改仓库代码。训练和评价由用户在 WSL 上执行，结果回传后再推到 GitHub。用户的 Windows 工作区在 `C:\Users\cjj\Desktop\IDP3\`。另有一方（Codex/独立评议者）会审阅本对话的产出。

## 2. 用户的工作思路（必须遵守）

1. **推进能力优先，不需要先完整证明根因。** 只要改动有合理依据、风险可控、结果可比较，就值得实验。组合实验如果有效，可以先保留，之后再做消融。
2. **区分两类问题：**
   - 措辞争议（"纯噪声""直接机制"之类）：降为工作假设即可，不要继续纠缠；
   - 会影响参数和程序的实际问题：必须在实现里落实，不能当成措辞问题放过。
3. **每个改进臂都必须有同父模型、同 seed、同预算的匹配对照。** 历史最好结果（C 的 182）只作参考，不作判定依据。
4. **test12 不是"只能用一次"。** 关键是不能用它的结果去改模型、选参数，再把后续结果称为独立验证。
5. **组合实验是工程效果实验，不是根因验证。** 开发检查（步骤 2、3）只用来控制成本、排除明显不合适的配置。
6. **希望 Kiro 给出自己的判断，不要顺着用户的话说。** 但要严格区分事实、复算、假设。用户和评议方会严查过强的结论。
7. **沟通偏好：** 用中文名称，不用无解释的字母代号。

### 4.2 当前判断（假设层级，不是已证明的根因）

1. **净收益主要来自目标 ≥3m 的任务，但不是因为学会了爬升 [复算]。** C 在高目标组新增的 66 个成功条件，起点中位高度 3.69m，目标 3.48m。BC 在这些条件下离目标最近时，水平距离中位数是 2.30m，C 是 0.45m。较准确的说法是"示范高度带之外的导航有改善"，原因未定。示范的目标高度在 [1,3]m，机体高度 90% 在 1.2–2.7m；训练和评价的目标高度按 U(1.5,4.5) 采样。
2. **越训越差不是必然的。** 同一个 u128 续训两次，A1 u256 得 129，C 得 182。两条路径在第一次更新时 policy_loss 就不同（0.0037069 对 0.0036964），差异来源尚未定位。结论是系统对很小的差异高度敏感，单次运行比较必须带运行噪声基准。
3. **保持项能防住流失，但压低新增。** 这是唯一有干预证据支持的机制。front_offset cfg03 这个窄余量任务，A1 u256 和 C 两次独立续训都是 5/5 碰撞，T 是 5/5 到达。但 T 的参考库固定为 BC/u128，所以在两者都失败的类别里，T 只新增 23，C 新增 51。
4. **绕障有小幅改善，没有突破。** 低高度密集受阻：BC 6，C 15。
5. **工作假设，等待改进实验验证：**
   - 有效动作通道的更新约束不足；
   - z 方向采样尺度和截断与"停在目标下方"有关。

### 4.3 [事实] 代码层面的确认

- **惰性通道：** 11 维动作中，速度、加速度、yaw rate（下标 3–8、10）不参与轻量环境的位置积分，但进入 PPO 概率比（88 个元素取均值）。**PX4 部署会使用这几维。** 在扩散去噪的中间步，它们会被下一次 U-Net 读取，所以只有最后一个去噪步上的噪声对环境确实没有后果。这一点 10-22 的审查已经讨论过，不是新发现。
- **代理 KL：** B2560 的 clip_fraction 约 0.08%，approx_kl 约 1e-5，KL 门禁从未触发。B1280 的 clip_fraction 是 3.9%。
- **截断：** BC 配置写的是 `clip_sample: True`，范围取 DDIMScheduler 默认值 1.0，没有专门标定。动作按逐维均值—标准差标准化，所以 ±1 等于示范的 ±1σ：Δz 每步 3.7cm，偏航每步 9.8°。DPPO 有意继承这个设置。
  - vendor `diffusion_vpg.py` 第 206–216 行先用**未截断**的 x0 推出 ε，再截断 x0，所以中间步仍有梯度；
  - 训练时在截断后还会再加噪，`final_action_clip_value=None`，所以 ±1σ 只是确定性评价的硬上限。
- **噪声下限：** 采样和 logprob 的下限都是标量 0.1，作用在归一化空间（scale：x 为 4.27，z 为 27.2）。同状态随机采样下，H4 标准差 x 4.7cm、y 4.8cm、z 0.8cm，三个策略几乎一样。
- **reward v2：** `terminal(+100/−50/0) + 10·(b−b′)/D0 + (−risk) − 0.05 + space`。其中 newbest 只奖励刷新历史最好距离；配置里的 `gamma_pbrs` 在 v2 中没有用到；space 每回合最多 −1。
- **训练环境：** 扰动 p=0.2、σ=0.3m，只在 H1–H3 未终止时施加；mid-state 初始化比例 0.3。
- **critic：** episode_context 6 维，零初始化；从 u128 fork 时，critic 和 Adam 状态都会恢复。

## 7. 踩过的坑

1. **用单次运行下结论。** A0、R1、fresh、B1280/B2560、C/T 都只跑了一次，结论一轮轮被推翻。同一父模型续训两次相差 53 个条件。教训：每个改进都要配匹配对照。
2. **只看总分不分层。** 低高度组净值接近 0，掩盖了保住 81、丢掉 22、新增 26 的大量替换；"密集组总数接近"也掩盖了受阻子集的差距。
3. **按名称或分组给能力命名。** "目标 ≥3m"被当成"爬升能力"，查完轨迹才知道主要是水平接近的问题；"初始直连通畅"也不等于全程无障碍。
4. **把元素个数占比当成梯度贡献占比**（64%），**把端点差除以轮数当成逐轮漂移**（5mm）。
5. **把确定性评价的边界套到训练采样上**（±1σ 截断）。
6. **口径不统一。** 受阻分层一开始用了自定义的"直连线间隙 <0.5m"，和既有的碰撞判据不一致，得到 110/105 的错误分母，附录里还错写成"0.1m 竖向膨胀"。
7. **测试替身漏掉真实接口。** A2 v1.1 的 138 项测试全部通过，但真实 E5 没有 `alphas_cumprod`，T 臂的标定直接崩溃。教训：必须用真实 runtime 做冒烟测试。
8. **BC 的碰撞数说得太绝对。** "BC 碰撞为 0"只在最容易的 100 个条件里成立，比较时要考虑环境难度。
9. **训练日志的横轴错位。** 第 u 轮 metrics 里的 rollout，是 u−1 的策略采集的。
10. **原 README 写的是 FM 主线，与实际不符**，实际是 E5 的 DDIM + x0 预测。仓库里有多条历史研究路线并存，以实际代码为准。
11. **沙箱环境：** 没有 numpy，统计脚本用纯 Python 写；仓库很大，`git pull` 要设 600s 超时；`behavior.json` 是 gzip 压缩的。

## 8. 被证明的经验

1. 评价是确定的。同一权重的 420 个结局可以逐条复现，A1 与 A2 的评价可以合并分析。
2. 保持类干预能阻止边界能力流失，而且很小的拉力就够（实际约 0.047 倍 PPO 梯度）。增大 λ 没有依据。
3. 固定参考库的保持会压低新增，参考库的来源决定了保护的是什么。
4. 更新组织对结果影响巨大：B1280 是 0/420，B2560 是 160/420。
5. 训练模式和确定性评价的到达率走势一致，退化在训练内部就已发生。
6. EV 正常不等于 critic 无问题，但 critic 不是"越训越差"的主要解释。
7. 先做轨迹级分层，再提机制，比先提机制再找证据可靠得多。
8. 回答"为什么"之前，先确认口径（分母、判据、横轴）。
