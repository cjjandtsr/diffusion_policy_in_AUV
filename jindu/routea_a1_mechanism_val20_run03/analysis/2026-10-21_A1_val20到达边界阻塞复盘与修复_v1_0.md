# A1 val20 到达边界阻塞：复盘与修复 v1.0

日期：2026-10-21。范围：Route A A1 val20 lightweight/kinematic 评价；不涉及新训练、test12或Gazebo/PX4。原始失败回传分别保留在 `wsl_snapshot/routea_a1_mechanism_val20_run01/` 和 `wsl_snapshot/routea_a1_mechanism_val20_run02/`，本文件不改写其证据。

## 1. 已确认事实与未证实解释

- [事实] v1.0 首跑在 checkpoint 身份加载失败。v1.1 恢复 A1 正式入口字节后，WSL 预检133文件闭包、四个 checkpoint 身份均匹配；u128 实际加载通过并执行到 val20 第3世界，说明第一阻塞已解除。
- [事实] v1.1 的 `run02` 在 `PairedEpisodeRecord.__post_init__` 抛 `reached must mean safe three-dimensional arrival within 0.5 m`。回传单世界复现记录的 `raw_done_reason=done_reason=reached`、安全标志为空、float32提交终点重算距离为 `0.5000000756965561 m`；超出名义半径约 `7.57e-8 m`。环境 reward v2 在实际H4路径上解算首次入球事件，再把事件位置转成float32提交；评价 core 从提交坐标用float64严格重算并要求 `≤0.5 m`。二者在球面边界不等价。
- [事实] 原运行在同世界 cfg02 崩，复现运行在 cfg03 崩，且复现的 cfg02 为 time_limit。说明至少该边界世界的重复运行记录不完全一致；现有证据不足以单独证明差异来自GPU非确定性、随机数流还是其他浮点路径。
- [推断] 在有权威 `raw_done_reason=reached` 且无安全失败标志的特定记录上，微小超界是float32提交舍入的合理解释；它不证明所有 `reached` 都物理安全。必须保持异常接纳范围极窄，并保留原坐标与超界量。

## 2. 全调用链复盘发现的两个连锁问题

第一，正式评价 core 的记录构造门禁用严格终点距离判 `reached`，与环境的连续线段首次入球事件冲突，导致80条件评价在第3世界中止。第二，同一记录类的 `success` 属性仍用严格 `final_distance_3d <= 0.5`。只改门禁会让环境真实报告 `reached` 的刀尖记录在成功率中被计为失败。两处必须同口径修正。

另一个潜在停机点在v1.1指导的跨 checkpoint BC 检查：它要求两次独立进程的BC整条记录逐字相等。既然回传已有同世界不同cfg触边界的重复运行差异，该断言可能误停；固定任务/seed不自动保证浮点记录逐字一致。v1.2改为固定条件身份严格相同，逐项报告BC记录及结局差异，不筛除、不覆盖，也不将有差异的重复运行冒称精确复现。

## 3. 修复内容及边界

受checkpoint身份保护的 `scripts/evaluate_dppo_uav_formal_endpoint.py`、`scripts/formal_endpoint_eval_core.py`、reward v2环境源码均保持原字节。闭包外现有 `scripts/run_routea_val20_endpoint.py` 加入明确的val20记录子类，仅在原core的**最后一个**到达门禁抛错时，且 `done_reason=raw_done_reason=reached`、无安全标志、目标存在、重算距离落在 `0.5m` 外但不超过舍入界，才接纳记录。舍入界是 `max(1e-6m, float32终点三坐标半ULP的欧氏范数+1e-9m)`；这是米制位置舍入界，不是first-event的时间tie tolerance。接纳后的 `success` 与权威安全到达事件一致。其余原core验证仍执行；超过界限、未到达却入球、原始结局/安全标志冲突继续报错。

原终点坐标、原始事件和奖励没有改写。每次完整评价新输出 `arrival_boundary_audit.json`，记录调度入口SHA256、A1原正式入口SHA256、provenance SHA256、接纳数量、任务/策略/世界、原坐标、距离、超界量和该条允许界。checkpoint仍走原严格身份核验。此调整仅是评价解释层的版本化扩展，不应追溯改写旧420或A1训练结果；若需要跨版本比较旧评价，须单独统计边界受影响条数。

## 4. 验证与剩余风险

Windows本地6个定向unittest通过：20世界/80条件的val-only选择、test12不入参、调度入口不在身份闭包、回传实际三维坐标的76纳米超界接纳且记审计、超界过大/原始结局冲突/安全标志冲突/未到达入球拒绝。三文件Python3.8 AST解析、CLI启动检查及指导4段Bash语法检查通过；原正式入口 SHA256 仍为A1字节 `13455ae9d910d8426a91e5c5a55da16790430aa2f0f7fd0470c2dbfd672b5f38`。Windows没有WSL的GPU/E5真实闭环环境，不能在本地声称80条件通过或能力提升。

[风险] 新评价调度层在checkpoint身份闭包之外，需以独立文件hash和边界审计约束；这揭示历史身份闭包把评价专用代码与训练源码绑在一起的设计债。当前节点先完成最小可裁决评价，之后可设计训练身份与评价协议分离的版本化机制，不能通过重写旧checkpoint header或隐藏源码差异解决。

[风险] 重复BC或边界结局可能有跨进程差异。v1.2要求保留两次BC完整记录并报告差异，最终分析须给出边界敏感结果与不确定性，不能只报单个成功数。若run03再出现超出舍入界或非到达事件矛盾，应停下并核对完整H4线段与first-event，不继续放宽容差。
