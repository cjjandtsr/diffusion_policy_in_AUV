## 四、仍需用户决定：历史改写
**合并本分支只缩小检出后的工作区，不缩小仓库本身。** 被删文件仍保存在 git 历史里，克隆时仍会下载。要真正缩小仓库，需要改写 main 的历史，例如：

```
git filter-repo --invert-paths --paths-from-file <被删路径清单>
git push --force origin main
```

改写后所有旧提交的哈希都会变。这些文档里引用的哈希会失效：`15ad24e2`、`36dbc9b`、`47252d9`、`6efc8c42` 等。所以建议改写前先把整个现有仓库镜像推送到一个归档仓库，例如 `diffusion_policy_in_AUV_archive`，保住旧哈希的可查性。

这一步不可逆，并会影响所有现有克隆（WSL 侧上传所用的克隆需要重新克隆）。Claude 未执行，等用户决定。
